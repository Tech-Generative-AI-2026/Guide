문답 글이 많은 사전학습만으로 부족한 이유

질문: 사전학습 텍스트에도 질문과 답이 든 글이 많은데 왜 지시-응답 항목으로 따로 학습하는가

사전학습의 목표 = 문서 이어 쓰기

  • 학습 정답 = 웹 문서의 다음 토큰(4주차) → 질문 다음에 오는 내용 = 답만이 아님(시험지의 다음 문제, 게시판의 다른 질문, 목록의 다음 항목)
  • 2장 사전학습 GPT-2의 출력: 답 대신 다음 "### Instruction:" 작성 = 지시문 목록 문서의 다음 항목으로 이어 씀
  • 요즘 base 판(Qwen2.5-7B 등, 3장): 사전학습 데이터의 문답 글 덕분에 질문 형식만 맞추면 꽤 답함, 그러나 답한 뒤 멈추지 않고 다음 질문을 지어내거나 지시 형식을 놓치는 일이 잦음 → 제작사가 대화용으로 비권장
  • 결과: 질문 뒤의 답 = 여러 이어 쓰기 후보 중 하나, 답하고 멈추는 행동은 고정되지 않음

지시 미세조정이 고정하는 것 = 차례와 멈춤

  • 모든 학습 텍스트 = 지시 → 응답 → 응답 끝 표시(50256)의 같은 순서 → 지시 다음 위치의 정답 = 늘 응답 첫 토큰, 응답 다음 정답 = 늘 끝 표시
  • 근거 연구 LIMA(Zhou et al., 2023 = 제1저자 Zhou 외, 발표 연도): 사전학습 모델 LLaMa 65B(Meta의 파라미터 650억 개 모델)를 엄선한 지시-응답 1,000개로만 지도 미세조정(SFT = 지시 미세조정, 3장) → 사람 평가에서 GPT-4 응답과 같거나 낫다는 판정 43%(GPT-4 = OpenAI의 상용 LLM)
  • 저자 가설(Superficial Alignment Hypothesis): 지식·능력은 거의 사전학습에서 학습, 미세조정은 사용자와 대화할 때 쓸 응답 형식을 학습 — 검증된 법칙이 아닌 가설
사전학습 = 지식과 여러 방향의 이어 쓰기, 지시 미세조정 = 새 지식 추가보다 '지시 다음엔 답하고 멈춘다'는 행동의 고정

프롬프트 템플릿이 필요한 이유: 칸이 없는 토큰 한 줄 입력

질문: 지시문·보조 입력을 주고 응답이 정답과 다르면 손실을 크게 주면 되는데, 왜 세 칸을 템플릿으로 한 줄로 잇는가

지시 데이터셋 항목 data[50](세 키의 딕셔너리)과 템플릿을 적용한 학습 텍스트

{'instruction': 'Identify the correct spelling of the following word.', 'input': 'Ocassion', 'output': "The correct spelling is 'Occasion.'"}
Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
Identify the correct spelling of the following word.

### Input:
Ocassion

### Response:
The correct spelling is 'Occasion.'
  • 항목의 키: "instruction" = 지시문, "input" = 보조 입력(지시문이 다룰 대상, 1,100개 중 775개는 빈 문자열), "output" = 원하는 응답

제약: GPT 입력 = 토큰 ID 한 줄

  • GPTModel 입력 = [batch, 토큰 수] 토큰 ID 텐서 하나(4·9주차), 지시문 칸·응답 칸 같은 별도 입력 자리 없음 → 세 칸을 텍스트 한 줄로 이어야 입력 가능
  • 한 줄 = 줄바꿈 문자도 토큰이 되어 이어진 토큰 ID 하나의 열(텐서의 한 행), 화면의 줄 수 아님
  • "응답이 다르면 손실을 크게" = cross_entropy가 이미 하는 일(정답 토큰 확률이 낮을수록 손실 큼, 9주차) → 새로 필요한 것 = 한 줄 안에서 응답이 시작하는 위치의 표시

해결: 프롬프트 템플릿(prompt template)

  • 정의: 항목의 칸들을 정해진 안내문·머리말과 함께 텍스트 하나로 잇는 고정 양식, 이 강의 = Alpaca 양식(Stanford 연구진이 2023년 공개한 지시 미세조정 모델 Alpaca가 쓴 양식)
  • 모든 학습 텍스트에서 응답 바로 앞 = "### Response:" → 사용 때도 이 머리말까지 넣으면 모델이 그 뒤를 응답으로 이어 씀
  • 보조 입력이 빈 항목 = "### Input:" 칸 생략
프롬프트 템플릿 = 칸이 없는 한 줄 입력 안에 지시문·보조 입력·응답의 경계를 고정 머리말로 표시하는 양식, 손실 계산 방식은 사전학습과 같음

응답까지 넣은 학습 입력에서 다음 토큰을 맞히는 방식

질문: 학습 때 응답까지 입력 한 줄에 넣으면 모델에게 답을 알려 준 것 아닌가 — 예시 항목 하나의 위치별 입력·정답

예시 항목(임의): 지시문 "Rewrite the sentence in passive voice.", 보조 입력 "Sarah baked the cake.", 응답 "The cake was baked by Sarah." → 템플릿 텍스트 = GPT-2 토큰 56개(위치 0~55), 응답 = 위치 49~55

위치 t위치 t가 볼 수 있는 토큰정답 = t + 1번 토큰
480~48: 안내문 ~ "### Response:" 줄The
490~49: … + The␣cake
50… + ␣cake␣was
51… + ␣was␣baked
52… + ␣baked␣by
53… + ␣by␣Sarah
54… + ␣Sarah.
55… + .<|endoftext|>
  • 위치 0~47 행 생략(같은 규칙), ␣ = 공백 문자, 위치 = 0부터 센 토큰 번호, 마지막 정답 <|endoftext|>(50256) = 응답 끝 표시

답을 미리 보지 못하는 이유: causal mask(6주차)

  • 위치 t의 출력 = 토큰 0~t만 참조, 맞힐 정답 = t + 1번 토큰 → 정답은 그 위치에서 가려진 미래
  • 한 번의 계산으로 56개 위치 모두의 "앞부분 → 다음 토큰" 문제를 동시에 풂(표 = 그중 응답 쪽 8개) = 사전학습(9주차)과 같은 방식

teacher forcing

  • 정의: 학습 때 각 위치의 앞부분에 모델이 생성한 토큰 대신 데이터의 정답 토큰을 넣는 방식 → 위치 49는 위치 48의 예측과 상관없이 정답 "The"를 보고 다음 토큰을 맞힘

학습 입력과 사용 입력

  • 학습: 56개 토큰 전체 한 줄(응답 포함), 손실 = 위치별 다음 토큰 정답의 cross_entropy
  • 사용: 위치 0~48의 49개 토큰("### Response:" 줄까지)만 입력 → 생성한 토큰을 붙여 반복(10주차 generate_text_simple), 응답은 모델이 생성
응답이 입력에 있어도 각 위치는 앞부분만 보고 다음 토큰을 맞힘 → 답을 준 것이 아니라 응답 토큰마다 맞히기 문제를 만든 것

템플릿 없이 물어도 답하는 이유

질문: 사용자는 "### Instruction:" 같은 머리말 없이 자유로운 말투로 묻는데 모델은 어떻게 답할 차례를 아는가

이유 1: 프로그램이 채팅 템플릿을 자동 적용

채팅 템플릿(chat template) = 대화를 역할(system: 기본 안내, user: 사용자, assistant: 모델)별 경계 토큰으로 감싸 한 줄로 잇는 프롬프트 템플릿, 모델마다 다름

messages = [{"role": "user", "content": user_text}]
print(tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True))
<|im_start|>system
You are Qwen, created by Alibaba Cloud. You are a helpful assistant.<|im_end|>
<|im_start|>user
Identify the correct spelling of the following word.
Ocassion<|im_end|>
<|im_start|>assistant
  • tok = Qwen2.5-1.5B-Instruct tokenizer(Hugging Face transformers 라이브러리), user_text = 사용자가 친 글(data[50] 지시문 + 보조 입력)
  • 템플릿이 붙인 것: system 문장, 역할 경계 <|im_start|>·<|im_end|>, 끝의 "<|im_start|>assistant" = add_generation_prompt=True가 붙인 응답 시작 표시

이유 2: 다양한 과제·말투의 지시 데이터

  • FLAN(Wei et al., 2021): 기존 NLP(자연어 처리) 데이터셋 62개마다 말투가 다른 지시 템플릿 10개를 사람이 써서 같은 과제를 여러 표현으로 학습
  • 결과: 학습에 없던 과제 데이터셋 25개 중 20개에서 예시 없이 지시문만 준 평가(zero-shot) 성능이 GPT-3 175B(파라미터 1,750억 개)보다 높음
  • 해석(추론): 여러 표현의 요청 → 같은 응답 행동, 처음 보는 말투도 요청으로 처리

지시 미세조정 뒤의 선호도 학습과 손실 범위 연구

질문: 상용 LLM은 지시 미세조정 뒤 무엇을 더 학습하며, 지시문 위치를 손실에서 빼는 선택은 늘 옳은가

선호도 학습(preference learning)

  • 정의: 같은 요청에 대한 두 응답 중 사람이 고른 쪽이 더 잘 생성되도록 하는 추가 학습, 데이터 = 정답 응답 하나가 아닌 응답 비교 쌍
  • RLHF — InstructGPT(Ouyang et al., 2022): ① 시연 데이터로 지도 미세조정 ② 비교 데이터로 보상 모델(응답 점수를 내는 모델) 학습 ③ 그 점수를 높이도록 강화학습(PPO) → 1.3B InstructGPT 응답이 파라미터 100배인 175B GPT-3 응답보다 선호됨
  • DPO(Rafailov et al., 2023): 별도 보상 모델·강화학습 없이 단순한 분류 손실로 같은 문제를 풂, Llama 3 후처리 학습에 사용

손실 범위 연구: Instruction Modelling(Shi et al., 2024)

  • 방법: 응답만이 아니라 지시문·프롬프트 위치에도 손실 적용 = 이 강의 코드의 기본 설정(10장 "padding only masked")과 같은 방향
  • 결과: 지시문이 길고 응답이 짧은 데이터, 학습 항목이 적은 경우에 특히 유리, 가장 유리한 경우 AlpacaEval 1.0(자동 응답 비교 평가) 점수 100% 넘게 향상, 저자 해석 = 과적합 감소
  • 판정: 응답만 손실(Llama 3)과 지시문 포함(Instruction Modelling) = 데이터 모양에 따라 결과가 갈리는 선택
대화형 LLM의 학습 순서 = 사전학습 → 지시 미세조정(지도 미세조정) → 선호도 학습(RLHF·DPO), 손실 범위는 데이터에 따라 정하는 설계 선택
