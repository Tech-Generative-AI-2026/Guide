GENERATIVE AI · SELF-ATTENTION

Outline

Self-Attention의 계산 원리: 같은 문장의 벡터를 비교하고, 기여 비율로 섞은 결과를 검산한다.

입력과 전달물

  • 입력은 여섯 토큰의 3차원 예시 벡터다. 토큰은 여기서 단어 하나에 대응한다.
  • 각 토큰에 문맥 정보를 섞은 벡터를 만들고 attention_report.py로 동료에게 계산·검산 결과를 전달한다.

계산과 성공 기준

  • 비교 점수 → 기여 비율 → 문맥 벡터를 계산한 뒤 전체 토큰으로 확장한다.
  • 입력과 출력은 [6,3], 기여 비율은 [6,6]이다. 각 행 합 1과 단일·전체 계산의 일치를 검산한다.
  • 학습 파라미터 없는 self-attention을 다룬다. 투영 행렬·미래 입력 차단·여러 attention의 병렬 구성은 포함하지 않는다.

02

단일 Hidden State의 정보 병목

입력을 압축하는 구성

  • 순환 신경망(RNN)은 이전 내부 상태와 현재 토큰을 읽어 새 상태를 만드는 신경망이다.
  • 그림의 encoder는 독일어 입력을 읽는 부분, decoder는 그 상태로 영어 출력을 만드는 부분이다.
  • 회색 상자는 중간 상태, 마지막 연결선은 입력 전체를 요약한 한 상태의 전달을 뜻한다.

접근 경로의 제약

  • 이 그림의 decoder에는 앞선 입력별 상태를 직접 다시 읽는 경로가 없다. 긴 문장의 단서가 약해질 수 있다.
  • 이는 모든 RNN의 필연적 실패가 아니라, 마지막 상태만 전달하는 구성의 제약이다.

03

Attention의 선택적 입력 접근

해결 원리

  • attention은 출력 하나를 만들 때 모든 입력 위치에 접근 가능한 경로를 둔다.
  • 선의 굵기는 해당 출력에 대한 입력의 상대적 기여도를 나타낸다.
  • 기여도는 수동 규칙이 아니라 뒤에서 계산할 attention weight로 정해진다.

관찰 기준

  • 두 번째 출력 you가 여러 입력과 연결되고 연결 강도가 서로 다른지 확인한다.

04

Self-Attention과 문맥 벡터

같은 문장 안의 비교

  • query(질의)는 문맥 벡터를 만들 기준 위치의 벡터다. 두 번째 단어 journey의 벡터를 선택한다.
  • self는 query와 비교·결합할 벡터가 같은 입력 X에서 나온다는 뜻이다. 번역 출력이 별도 원문을 읽는 경우와 구분한다.
  • 그림의 위 입력 → 선의 기여 비율 → 아래 문맥 벡터 순서로 읽는다. 문맥 벡터는 입력들을 비율에 따라 섞은 결과다.

입력과 결과의 대응

  • \(x^{(j)}\)는 j번째 입력, \(z^{(2)}\)는 두 번째 출력이다. \(\alpha_{2j}\)의 2는 기준 위치, j는 기여할 입력 위치다.
  • 가운데 점은 생략된 입력을 뜻한다. 실제 계산은 여섯 입력 모두를 포함하며 결과는 후속 모델 연산에 전달한다.

고정 입력 임베딩 행렬

재현할 입력

  • attention_report.py의 첫 부분이다. import torch는 PyTorch 계산 도구를 불러온다.
  • torch.tensor는 6행 3열 실수 배열을 만든다. 행은 Your … step 순서, 열은 특징 좌표다.
  • 수치는 계산용으로 주어진 예시다. 실제 학습된 의미나 위치 임베딩을 계산한 결과라고 가정하지 않는다.

확인할 출력

  • shape는 축 길이, dtype은 수의 저장 형식이다. float32는 32비트 실수다.

import torch

    [0.57, 0.85, 0.64],  # starts
    [0.22, 0.58, 0.33],  # with
    [0.77, 0.25, 0.10],  # one
    [0.05, 0.80, 0.55],  # step
])
print(inputs.shape, inputs.dtype)

06

Dot Product Attention Score

내적과 점수

  • 내적(dot product)은 두 벡터의 같은 열끼리 곱한 뒤 합한 수다. 이 비교 점수를 attention score라 부른다.
  • Your와 journey의 점수: 0.43×0.55 + 0.15×0.87 + 0.89×0.66 = 0.9544.
  • 입력 [3] 두 개를 합산해 스칼라(수 하나)를 얻는다. 점수는 아직 기여 비율이 아니다.

해석의 한계

  • 내적에는 방향과 벡터 길이가 함께 작용한다. query=[1,0]이면 [1,0]의 점수는 1, [2,2]는 2다.
  • 점수가 더 큰 [2,2]가 query와 더 같은 방향은 아니다. 이 예시의 점수만으로 의미 유사도를 단정할 수 없다.

07

Attention Score의 실제 계산

한 토큰의 점수 계산

  • inputs[1]은 0부터 세어 두 번째 행을 query로 고른다. inputs @ query는 여섯 내적을 계산한다.
  • 그림의 위 입력과 초록 query를 비교해 파란 점수 \(\omega_{2j}\) 하나씩을 얻는다. j는 입력 위치다.
  • 출력 [6]의 첫 값 0.9544가 손계산과 같다. 그림은 값을 짧게 잘라 표시하므로 아래 실제 수치로 검산한다.
Python · attention_report.py
query = inputs[1]
attn_scores_2 = inputs @ query
print(attn_scores_2)
실행 결과
tensor([0.9544, 1.4950, 1.4754, 0.8434, 0.7070, 1.0865])

08

Score 정규화의 선택 기준

합으로 나눌 때의 실패

  • score=[−1,2]를 합 1로 나누면 [−1,2]다. 합은 1이지만 음수는 기여 비율로 쓰기 어렵다.
  • score=[−1,1]이면 합이 0이라 나누기를 정의할 수 없다. 입력 점수에 부호가 섞일 수 있다.

Softmax의 해결과 경계

  • softmax는 \(a_j=e^{s_j}/\sum_k e^{s_k}\)이다. s는 점수, j·k는 입력 위치, e≈2.718은 지수의 밑이다. [−1,2]는 약 [0.0474,0.9526]이 된다.
  • 유한 점수의 정확한 수학값은 양수다. 컴퓨터에서는 매우 작은 비율이 0으로 저장될 수 있으므로 음수 없음과 행 합을 검산한다.
  • 실제 코드는 안정적인 torch.softmax를 사용한다.

09

Softmax Weight의 수치 검증

점수에서 기여 비율로

  • 그림의 파란 점수 \(\omega_{2j}\)를 정규화하면 노란 비율 \(\alpha_{2j}\)가 된다. dim=0은 이 1차원 벡터 전체를 계산 대상으로 삼는다.
  • sum()은 모든 비율의 합이다. allclose는 두 값이 허용 오차 안에서 같은지 판정한다.
  • atol=1e-6은 절대 오차 백만분의 1, rtol=0은 추가 상대 오차 없음이다. 계산에는 반올림 전 값을 사용한다.
Python · attention_report.py
attn_weights_2 = torch.softmax(attn_scores_2, dim=0)
print(attn_weights_2)
print(torch.allclose(attn_weights_2.sum(),
                     torch.tensor(1.), atol=1e-6, rtol=0))
실행 결과
tensor([0.1385, 0.2379, 0.2333, 0.1240, 0.1082, 0.1581])
True

문맥 벡터의 가중합

같은 위치의 비율과 입력 결합

  • 가중합은 각 비율 \(\alpha_{2j}\)를 같은 위치 입력의 세 좌표 모두에 곱한 뒤 좌표별로 더하는 연산이다.
  • [6] @ [6,3]은 여섯 입력을 합쳐 세 특징을 남긴다. 비율의 위치와 입력 행의 짝을 유지해야 한다.
  • 그림은 중간 입력을 생략한다. 마지막 비율의 α₂₄ 표기는 α₂T로 읽는다. 결과 [0.4,0.6,0.5]는 잘라 쓴 값이며 정상 반올림은 [0.4,0.7,0.6]이다.
Python · attention_report.py
context_vec_2 = attn_weights_2 @ inputs
print(context_vec_2)
실행 결과

개별 기여의 합산과 문맥 벡터

좌표별 합산

  • [:,None]은 여섯 비율 [6]을 [6,1]로 바꾼다. 콜론은 모든 행, None은 길이 1인 축 추가이다.
  • * inputs는 비율 하나를 같은 행의 세 좌표에 적용한다. 결과 [6,3]의 각 행은 입력 하나의 기여다.
  • sum(dim=0)은 기여 행 여섯 개를 합친다. @와 같은 context를 얻는다. 첫 좌표의 기여 약 [0.0596,0.1308,0.1330,0.0273,0.0833,0.0079]를 더하면 0.4419다.
Python · attention_report.py
contributions = attn_weights_2[:, None] * inputs
print(contributions.shape)
print(contributions.sum(dim=0))
print(torch.allclose(contributions.sum(dim=0),

Attention Weight 행렬의 축

행과 열의 의미

  • 이제 한 query 계산을 여섯 query로 확장한다. 행 i는 기준 토큰, 열 j는 기여하는 입력 토큰이다.
  • 노란 두 번째 행의 journey→starts 값은 약 0.2333이다. 반대 방향 starts→journey는 약 0.2369다.
  • 그림은 소수 둘째 자리까지 잘라 표시한다. 표시값의 행 합이 1보다 작아도 실제 값으로 검산해야 한다.

모든 Score의 행렬 계산

한 query에서 전체 query로

  • inputs.T는 [6,3]을 [3,6]으로 전치한다. inputs @ inputs.T는 토큰 쌍 36개의 내적을 [6,6]에 모은다.
  • 셀 (i,j)는 i번째 기준 토큰과 j번째 입력의 점수다. 같은 두 벡터의 내적이므로 점수 행렬은 대칭이다.

행 단위 Softmax의 불변 조건

행마다 별도의 분포

  • dim=-1은 마지막 축, 즉 열을 따라 각 행을 따로 정규화한다. 기준 토큰 하나가 여섯 입력에 나눠 줄 비율이다.
  • sum(dim=-1)은 각 행을 더해 길이 6의 벡터를 만든다. ones(6)은 1 여섯 개를 만들어 비교 기준으로 쓴다.
  • 행 합이 1이어도 토큰 순서가 뒤섞일 수 있다. 뒤의 가중합에서는 열 j와 입력 행 j의 짝도 보존해야 한다.
Python · attention_report.py
attn_weights = torch.softmax(attn_scores, dim=-1)
print(attn_weights.sum(dim=-1))
print(torch.allclose(attn_weights.sum(dim=-1),
                     torch.ones(6), atol=1e-6, rtol=0))
실행 결과
tensor([1.0000, 1.0000, 1.0000, 1.0000, 1.0000, 1.0000])
True

점수 대칭과 기여 비율의 비대칭

서로 다른 정규화 기준

  • score의 (i,j)와 (j,i)는 같은 내적이다. 하지만 softmax의 분모는 각 query 행 전체의 지수 합이다.

단순 Self-Attention의 역할과 한계

확인한 결과

  • X:[6,3] → S:[6,6] → A:[6,6] → Z:[6,3]이며 두 번째 출력은 [0.4419,0.6515,0.5683]이다.
  • A의 각 행은 현재 입력으로 계산한 기여 비율이다. 입력이 바뀌면 다시 계산한다.
  • X를 고정한 이 연산에는 학습으로 갱신할 별도 파라미터가 없다.

이 결과로 말할 수 없는 것

  • 행 합과 계산 일치는 구현을 검산하지만 실제 의미 이해나 번역 품질을 입증하지 않는다.
  • 토큰별 출력이 여섯 행이라는 사실은 입력 정보를 손실 없이 복원할 수 있다는 뜻도 아니다.
