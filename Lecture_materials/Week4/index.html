출발점과 도착점

  • GPT 개발 지도 → 자기지도 다음 토큰 예측 → sliding window와 batch 순서로 진행한다.
  • 마지막에는 토큰 임베딩과 위치 임베딩의 Shape을 맞춰 더한다.

토큰화와 임베딩의 선수 개념

이미 설명한 개념

  • BPE는 문자열을 서브워드 토큰으로 나누고 각 토큰을 정수 ID로 바꾼다.
  • 임베딩 층은 토큰 ID를 학습 가능한 연속 벡터의 한 행으로 조회한다.
  • 역전파는 다음 토큰 손실의 책임을 임베딩과 모델 파라미터에 전달한다.

이번 범위의 경계

  • BPE 병합 계산·one-hot 비교·XOR·손실함수·경사하강법은 다시 전개하지 않는다.
  • 이번에는 토큰 ID 열을 훈련 샘플과 위치가 포함된 입력 텐서로 조직한다.

tiktoken의 encode와 decode

실행 계약

  • encode는 문자열을 토큰 ID 목록으로 바꾼다.
  • decode는 ID 목록을 문자열로 복원한다.
  • 입력에 특수 토큰이 있으면 허용할 특수 토큰 집합을 명시한다.
python
import tiktoken

tokenizer = tiktoken.get_encoding("gpt2")
text = "Hello <|endoftext|> someunknownPlace"
ids = tokenizer.encode(text, allowed_special={"<|endoftext|>"})

assert tokenizer.decode(ids) == text

고정 길이 문맥의 필요성

Batch 행렬 계산의 조건

  • DataLoader가 여러 sample을 [B,T]로 쌓아 같은 행렬 연산을 적용하려면 한 batch 안의 token 길이 T가 같아야 한다.
  • 모든 데이터가 전역적으로 같은 길이일 필요는 없지만, 이 구현은 max_length=T인 고정 창을 사용해 매 batch의 직사각형 Shape을 보장한다.
  • 길이가 같은 행은 토큰 임베딩 뒤 [B,T,D]가 되어 batch·token 위치를 병렬로 계산할 수 있다.

짧거나 긴 입력의 처리

  • 짧은 문장별 sample은 batch의 최장 길이나 max_length까지 padding하고, padding 위치는 mask로 실제 문맥에서 제외한다.
  • max_length보다 긴 sample은 꼬리를 truncate하거나 여러 window로 분할하며, truncate는 제거한 정보를 잃고 window는 각 행 밖의 문맥을 직접 보지 못한다.
  • 이 연속 원문 사전학습 예제는 padding 대신 길이 T의 window를 반복 추출하고, stride로 다음 window의 시작점을 정한다.

한 원문에서 여러 예측 만들기

입력과 정답

  • 각 줄의 파란 토큰은 모델이 볼 문맥이고 바로 뒤의 붉은 토큰은 맞힐 정답이다.

다음 토큰 예측 학습 데이터 생성

앞에서는 주어진 토큰열로 다음 토큰을 생성하는 추론을 생각했다. 여기서는 긴 원문을 여러 입력·정답 쌍으로 바꿔, 각 위치에서 다음 토큰을 맞히도록 학습하는 과정을 본다.

원문에서 입력·정답 만들기

  • 파란 첫 행: 입력 x=[In, the, heart, of].
  • 빨간 첫 행: 한 칸 뒤 정답 y=[the, heart, of, the].
  • 같은 열의 In→the, the→heart, heart→of, of→the를 모두 학습한다.

Window의 행과 텐서 축

  • 각 행의 가로 방향 T는 순서대로 놓인 토큰이다.
  • 학습에서는 긴 원문에서 자른 window B개를 쌓는다. 임베딩 후 [B,T,D]이며 D는 토큰 벡터 길이다.

Sliding window의 두 조절값

max_length

  • max_length는 각 입력 행과 정답 행의 token 축 길이를 정한다.
  • 값이 커지면 모델이 한 샘플에서 볼 수 있는 앞 문맥이 길어진다.

stride

  • stride는 다음 입력 창의 시작 위치가 몇 토큰 이동하는지를 정한다.
  • stride가 max_length보다 작으면 이웃한 입력 행이 일부 토큰을 공유한다.

Stride 1과 4의 차이

같은 원문의 다른 sampling

  • 길이 4·stride 1은 다음 창이 한 칸 이동해 이웃한 input이 세 token 겹친다.
  • 길이 4·stride 4는 다음 창이 네 칸 이동해 이웃한 input이 겹치지 않는다.
  • stride는 다음 sample의 시작점 i를 옮기며 batch 번호를 바꾸지 않는다.

교재 그림의 라벨 교정

  • 그림의 Inputs of batch 1·2는 실제로 input window(sample) 1·2이며, 서로 다른 두 batch가 아니다.
  • DataLoader가 window B개를 batch로 묶는다. batch_size=8이면 한 batch에 input sample 8개가 들어간다.
  • 작은 stride는 sample 수와 중복을 늘리지만, 잘린 행 바깥의 문맥을 복원하지는 않는다.

GPTDatasetV1의 정의와 도입 목적

무엇이며 어디에 쓰이는가

  • GPTDatasetV1은 원문을 고정 길이 input-target sample로 바꾸는 이 강의용 PyTorch Dataset 클래스이다.
  • 이름의 V1은 교재의 첫 최소 구현을 뜻하며 GPT 모델 버전이나 PyTorch 내장 dataset 이름이 아니다.
  • 위치는 tokenizer → GPTDatasetV1 → DataLoader → GPT 입력 임베딩 순서이며, 모델 학습 전에 sample 생성 규칙을 맡는다.

왜 이 시점에 도입하는가

  • 앞 장표에서 확정한 max_length, stride, 한 칸 이동 규칙을 반복 가능한 코드 계약으로 묶기 위해 도입한다.
  • 생성 시 전체 원문을 한 번 encode하고 각 시작점의 두 구간을 torch.long tensor로 저장한다.
  • 조회 시 __getitem__(idx)가 sample 한 쌍을 반환하면 다음 단계의 DataLoader가 여러 sample을 batch로 묶는다.

GPTDatasetV1 구현

핵심 슬라이싱

  • 입력 구간은 i부터 i + max_length 직전까지이다.
  • 정답 구간은 입력 시작보다 한 칸 뒤에서 같은 길이만큼 뽑는다.
python
import torch
from torch.utils.data import Dataset

class GPTDatasetV1(Dataset):
    def __init__(self, txt, tokenizer, max_length, stride):
        self.input_ids = []
        self.target_ids = []
        token_ids = tokenizer.encode(txt)

        for i in range(0, len(token_ids) - max_length, stride):
            x = token_ids[i:i + max_length]
            y = token_ids[i + 1:i + max_length + 1]
            self.input_ids.append(torch.tensor(x))
            self.target_ids.append(torch.tensor(y))

    def __len__(self):
        return len(self.input_ids)

    def __getitem__(self, idx):
        return self.input_ids[idx], self.target_ids[idx]

DataLoader의 책임

샘플에서 batch로

  • batch_size는 한 번에 묶을 입력·정답 행의 수를 정한다.
  • shuffle=True는 epoch마다 행의 학습 순서를 섞는다.
  • drop_last=True는 행 수가 부족한 마지막 batch를 제외해 batch Shape을 일정하게 만든다.
python
from torch.utils.data import DataLoader

dataset = GPTDatasetV1(raw_text, tokenizer, max_length=4, stride=4)
dataloader = DataLoader(
    dataset,
    batch_size=8,

위치 임베딩의 생성

[T, D] 위치 표

  • 위치 임베딩 층은 최대 문맥 길이만큼의 행과 토큰 임베딩과 같은 차원 D를 가진다.
  • torch.arange(T)는 현재 입력의 위치 번호 0부터 T-1까지를 만든다.
  • 현재 token 수 T는 모델이 지원하는 최대 문맥 길이를 넘지 않아야 한다.
python
T = inputs.shape[1]
position_embedding = torch.nn.Embedding(4, D)
positions = torch.arange(T)
position_embeddings = position_embedding(positions)

assert position_embeddings.shape == (4, 256)

End-to-end Shape 추적

한 batch의 변환

  • inputs와 targets는 각각 [B, T] 정수 ID 텐서이다.
  • token_embeddings는 [B, T, D]이고 position_embeddings는 [T, D]이다.
  • 최종 input_embeddings는 [B, T, D]이며 targets는 손실 계산용 [B, T]로 남는다.
text
raw text

          ├─ sliding window ──> inputs  [B, T]
          │                     targets [B, T]
          └─ token embedding ─> [B, T, D]
               + position embedding [T, D]
               └──────────────> input embeddings [B, T, D]
