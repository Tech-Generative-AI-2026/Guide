# 기말프로젝트: Tiny Synthetic Language Modeling

작은 GPT 계열 언어모델을 직접 설계하고 학습해, 공개되지 않은 암호문 문제의 답을 가장 정확하게 맞히는 과제입니다.
자연어 성능 경쟁이 아니라, 모델이 **비공개 규칙으로 만들어진 언어를 얼마나 잘 학습하고 일반화하는지** 봅니다.

## 공지 (2026-11-19): 데이터 교체와 평가 방식 확정

**데이터 교체**
- `data/level1/`을 지우고 새 데이터 `data/level5/`로 바꿨습니다. 변환 규칙의 **키를 새로 정했고**, 평가는 **5단계 하나**로만 합니다.
- 어휘, 문제 구조의 종류, 문제 길이를 늘렸습니다. 줄 수는 그대로 train 1,800줄, val 180줄입니다.
- 이전 1단계 데이터와, 그 데이터에서 알아낸 키·대응표는 더 이상 맞지 않습니다.
- 11-19 leaderboard에서 알린 11-26 2단계 공개는 **취소**합니다. 앞으로 단계를 더 공개하지 않습니다.
- 문제가 길어졌으므로 `config.json`의 `block_size`를 새 데이터에 맞게 고칩니다(baseline은 96). 본인 저장소에 새 `data/level5/`, `submission/tokenizer.py`, `submission/config.json`, `submission/train.py`, `submission/train_config.json`을 Guide에서 복사해 반영합니다.

**평가 방식 (2026-11-25(수) 13:00 평가부터 최종 평가까지)**
- 교수자 PC가 제출한 `submission/train.py`로 모델을 **처음부터 다시 학습**하고, 그 모델을 채점합니다(재학습 평가).
- 학습 데이터는 공개하지 않는 **hidden train/val**입니다. 공개 train/val과 **같은 크기(1,800/180줄)이고 같은 방식으로 만들었지만, 공개하지 않는 다른 키**로 암호화했습니다. 채점은 같은 키로 만든 hidden test로 합니다.
- 공개 train/val은 여러분이 본인 PC에서 개발하는 데 씁니다. hidden train이 공개 train과 크기·만드는 방식이 같으므로, 공개 train/val로 정한 epoch 수와 early stopping 규칙이 재학습에서도 그대로 통합니다.
- 제출 파일에 `train.py`와 **`train_config.json`**(학습 하이퍼파라미터 파일)이 추가됩니다. epoch 상한은 **200**, 학습 시간 상한은 **1,800초**입니다. 자세한 내용은 [재학습 평가](#재학습-평가-2026-11-25수-평가부터)를 봅니다.
- **바뀌는 이유**: 모든 학생을 컴퓨팅 자원과 무관하게 공정하게 평가하기 위해서입니다. 제출한 weight를 그대로 채점하면, 공개 train에서 알아낸 키로 가능한 문제를 모두 만들어 학습하거나 300,000 parameter보다 큰 모델의 출력으로 학습한 weight를 막을 수 없습니다. 재학습 평가에서는 같은 GPU·같은 시간 상한·처음 보는 키의 데이터로 학습하므로 **학습 알고리즘과 연구 내용만** 점수를 가릅니다.

**제출 안내**
- 코드·설정·학습 weight·실험 기록을 바꿀 때마다 commit하고 push합니다. 평가 때 GitHub에 push되어 있지 않은 변경은 평가 대상이 아닙니다.
- 기말프로젝트 기간에는 최종 마감까지 push 권한을 유지합니다.

## 1. 용어

- **평문**: 교수자가 만든 제한된 영어 문제와 답. 공개하지 않습니다.
- **암호문**: 평문을 비공개 변환 규칙으로 바꾼 문자열. 여러분에게 주어지는 데이터는 모두 암호문입니다.
- **단계(level)**: 변환 규칙의 등급. 1–5단계가 있고 단계가 오를수록 규칙이 더 섞입니다. 이 과제는 **5단계 하나**만 씁니다(`data/level5/`). 단어를 기호로 1:1 바꾸는 방식이 아니며, 규칙은 공개하지 않습니다.
- **키**: 변환 규칙에 쓰는 비공개 대응표. 같은 규칙이라도 키가 다르면 같은 평문이 다른 암호문이 됩니다. 공개 데이터와 재학습 평가 데이터는 키가 다릅니다.
- **해독**: 교수자 채점기가 암호문 답을 평문으로 되돌리는 과정. 학생 코드는 해독에 관여하지 않습니다.

## 2. 주어진 것

| 경로 | 내용 |
|---|---|
| `data/level5/train.txt` | 공개 학습 데이터 1,800줄. 형식은 `암호문 문제<SEP>암호문 답<EOS>` |
| `data/level5/val.txt` | 공개 개발 데이터 180줄. 형식은 train과 같음 |
| `submission/model.py` | baseline GPT. `build_model(config)`와 `forward(idx)`를 제공 |
| `submission/tokenizer.py` | 문자 단위 토크나이저. `encode`, `decode`, `SEP_ID`, `EOS_ID` 제공 |
| `submission/config.json` | 모델 하이퍼파라미터 |
| `submission/train.py` | baseline 학습 코드. 재학습 평가가 실행하는 학습 진입점. `--data`, `--out`, `--seed`를 받음 |
| `submission/train_config.json` | baseline 학습 하이퍼파라미터(`epochs`, `batch_size`, `lr` 등). `train.py`가 읽음 |
| `train.py` | `submission/train.py`를 기본값으로 실행하는 바로가기. `submission/checkpoint.pt`를 저장 |
| `dev_score.py` | 개발 점수 확인. 암호문 답의 완전 일치만 봅니다 |
| `requirements.txt` | 허용 패키지 목록 (`torch==2.8.0`) |

hidden test(비공개 테스트 문제)는 주지 않습니다. hidden test는 train에서 배울 수 있는 규칙으로 풀 수 있는 처음 보는 문제이며, 문제의 조합·길이·구조·어휘가 train과 다를 수 있습니다. 문제 수와 구성은 공개하지 않습니다. 최종 채점은 교수자 PC에서 실행합니다.

## 3. 데이터와 과제

### 데이터

- 한 줄이 문제 하나입니다. 형식은 `암호문 문제<SEP>암호문 답<EOS>`이고, `<SEP>`와 `<EOS>`는 암호화하지 않는 예약 문자열입니다.
- 평문은 교수자 생성기가 만든 짧은 영어 문제와 답이며, 몇 가지 문제 유형이 섞여 있습니다. 평문, 문제 유형, 어휘, 변환 규칙은 마감 전에 공개하지 않습니다.
- 암호화는 공백을 포함한 문자열 전체를 **문자 단위로** 바꿉니다. 같은 평문 글자도 위치와 앞 글자에 따라 다른 기호가 될 수 있어서, 단어를 기호 하나로 바꾸는 사전처럼 풀리지 않습니다. 기호는 ASCII와 Unicode 문자를 함께 씁니다.
- 공개 train 기준으로 한 줄은 토큰 93개 이하이고, 암호문 답은 1–28글자입니다. hidden test 문제와 답은 이보다 길 수 있으니 모델의 입력 길이(`block_size`)와 생성 길이에 여유를 두세요.
- 공개 데이터는 train 1,800줄, val 180줄입니다. 재학습 평가의 hidden train/val도 같은 크기(1,800/180줄)이고 같은 방식으로 만들었으며, 키만 다릅니다.
- hidden train/val과 hidden test에는 공개 train·val과 똑같은 문제를 넣지 않고, 서로도 겹치지 않습니다. train의 문제를 외운 모델이 아니라 규칙을 배운 모델이 높은 점수를 받도록 만듭니다.

### 과제: 암호문 문제를 읽고 암호문 답을 생성하기

모델은 `암호문 문제<SEP>`를 입력받아 다음 토큰을 하나씩 생성하고, `<EOS>`를 내면 멈춥니다. `<SEP>`와 `<EOS>` 사이에 생성한 문자열이 모델의 답입니다. 모델은 평문을 볼 수 없으므로 암호문만으로 "이런 문제 뒤에는 이런 답이 온다"는 규칙을 배워야 합니다.

**쉬운 예제 (설명용 가짜 규칙).** 실제 규칙과 문제는 이것과 다르며 훨씬 복잡합니다. 설명을 위해 "알파벳은 다음 글자로, 공백은 `·`로 바꾸는" 가짜 규칙을 씁니다.

| 단계 | 내용 |
|---|---|
| 평문 문제와 답 (여러분은 볼 수 없음) | `sky color ?` → `blue` |
| train 한 줄 (여러분이 받는 형태) | `tlz·dpmps·?<SEP>cmvf<EOS>` |
| 채점 때 모델 입력 | `tlz·dpmps·?<SEP>` |
| 모델이 생성한 답 | `cmvf` 다음 `<EOS>` |
| 교수자 채점기가 해독한 답 | `blue` → 정답과 같으므로 10점 |

비유하면 외국어 문제집을 정답과 함께 받아 공부한 뒤, 처음 보는 문제를 같은 외국어로 답하는 시험입니다. 다만 실제 외국어와 달리 이 언어는 사전이나 번역기가 없고, 문제집(train)이 유일한 자료입니다.

## 4. 실행

```bash
pip install -r requirements.txt
python train.py       # baseline 학습 (CPU 몇 분 이내). python submission/train.py와 같음
python dev_score.py   # 개발 점수 확인
```

baseline은 3 layer, 4 head, 80 embedding, 248,560 parameter이고, `train_config.json`에 따라 54 epoch(batch 32) 학습합니다. GPU가 있으면 `submission/train.py`가 GPU로 학습합니다. 교수자 PC GPU에서 baseline 학습은 약 20초(epoch당 약 0.37초)입니다.

재학습 평가와 같은 방식으로 실행해 보려면 학습 결과를 다른 폴더에 쓰게 합니다.

```bash
python submission/train.py --data data --out /tmp/retrain_out --seed 0
```

## 6. 제약

- parameter 수는 **300,000 이하**입니다. 학습 여부와 무관하게 모델의 모든 parameter와 buffer 원소 수를 더합니다. 학습하지 않게 고정한 weight와 `register_buffer`로 등록한 tensor도 포함됩니다. `train.py`가 출력하는 값이 채점과 같은 방식입니다.
- 채점 때는 `submission/`의 제출 파일 5개만 복사해 실행합니다. `model.py`와 `tokenizer.py`는 다른 파일을 읽으면 안 되고, 각각 50KB 이하여야 합니다. weight는 `checkpoint.pt`에만 둡니다.
- 학습 데이터는 `--data`로 받은 train/val 줄뿐입니다. 아래 [재학습 평가의 학습 규칙](#재학습-평가의-학습-규칙)을 따릅니다.
- 외부 자연어 말뭉치, 외부 pretrained weight, 외부 API 출력 데이터는 사용할 수 없습니다.
- **300,000 parameter보다 큰 모델을 teacher로 쓰거나, 그 출력으로 distillation하는 것은 금지**입니다. 학습 코드 안에서든 본인 PC에서든 같습니다. 컴퓨팅 자원과 무관하게 모두를 공정하게 평가한다는 원칙 때문입니다.
- `requirements.txt`에 없는 패키지는 사용할 수 없습니다.
- `model.py`와 `tokenizer.py`는 import할 때 파일을 쓰거나, 프로세스를 실행하거나, 외부에 접속하면 안 됩니다.
- hidden test 실행 시에는 네트워크를 쓰지 않습니다.

### 참고 구현 사용 조건

[train-llm-from-scratch](https://github.com/FareedKhan-dev/train-llm-from-scratch)(MIT 라이선스)는 순수 PyTorch 구현을 읽고 참고할 수 있습니다.
- 코드를 옮겨 쓸 수는 있으나, 옮긴 부분에는 출처와 MIT 라이선스를 README에 적습니다.
- 그 repo가 쓰는 데이터(The Pile)와 그 repo로 학습한 weight는 사용할 수 없습니다.
- 그 repo를 패키지로 설치해 import하는 것은 허용되지 않습니다.
- 참고 구현의 기본 모델(13M)은 상한을 넘으므로 layer 수와 embedding 차원을 줄여야 합니다.

본인 GitHub 저장소(수업 실습에 쓰는 `Tech-Generative-AI-2026/<GitHub ID>_<번호>`)의 **`FinalProject/submission/`** 폴더에 아래 파일을 두고 기본 branch(`main`)에 push합니다. 경로가 다르면 미제출로 처리됩니다.

```text
FinalProject/submission/
  model.py        # 모델 정의
  tokenizer.py    # 토크나이저
  config.json     # 하이퍼파라미터, vocab_size, block_size, parameter 수
  checkpoint.pt   # model.state_dict()만 저장한 학습 weight
  README.md       # 실험 아이디어, 구조, 변경점, dev 점수, 실패한 시도
  train.py        # 학습 코드 (재학습 평가부터 필수). checkpoint.pt를 만든 코드
  train_config.json  # 학습 하이퍼파라미터 (재학습 평가부터 필수). checkpoint.pt를 만든 설정 그대로
```

- 재학습 평가부터는 `train.py`, `train_config.json`까지 7개가 필수입니다. 학습 코드가 쓰는 보조 모듈은 `submission/` 바로 아래 `.py` 파일로 둡니다. 실험 기록과 실험용 스크립트는 repo의 다른 위치에 자유롭게 둡니다.
- `checkpoint.pt`는 재학습 평가에서도 계속 제출합니다. 제출한 `train.py`가 이 checkpoint를 만든 코드인지 확인하는 **재현성 비교**에 씁니다.
- `checkpoint.pt`는 `torch.save(model.state_dict(), ...)`로 저장합니다. 평가는 `torch.load(..., weights_only=True)`로 읽습니다.
- `checkpoint.pt`는 Git LFS를 쓰지 말고 파일 그대로 commit합니다. 300,000 parameter면 약 1.2MB입니다.
- `config.json`의 `block_size`는 채점 때 모델에 넣는 최대 길이입니다. 공개 데이터의 가장 긴 `문제<SEP>답<EOS>`(93토큰)보다 짧으면 안 됩니다.

## 8. 평가 방식

### 평가 절차

1. 교수자 PC가 여러분 저장소의 마지막 commit에서 `FinalProject/submission/`만 내려받습니다.
2. 제출 파일 5개와 소스 크기를 검사하고, 5개만 네트워크가 끊긴 격리 환경(`requirements.txt`와 같은 torch 2.8.0 CPU)에 복사합니다.
3. `checkpoint.pt`와 모델의 parameter·buffer 원소 수를 세어 300,000 이하인지 확인합니다.
4. 채점기가 hidden test 문제마다 `암호문 문제<SEP>`를 넣고 **greedy decoding**으로 답을 생성합니다. greedy decoding은 매 단계 확률이 가장 높은 토큰 하나를 고르는 방식이며, `<EOS>`가 나오거나 64토큰에 이르면 멈춥니다. 여러분의 코드는 `build_model`, `forward`, `encode`, `decode`만 실행되고 decoding과 채점에는 관여하지 않습니다.
5. 채점기가 생성된 암호문 답을 해독해 평문 단어로 바꾸고, 정답 단어와 비교해 **문제 점수**를 매깁니다.
6. 문제 점수의 평균으로 **score**를 계산합니다.
7. 최종 점수 순위와 비공개 시험 손실 순위를 50%씩 반영해 종합 순위를 정합니다.

`dev_score.py`는 같은 생성 방식으로 val을 풀지만, 해독 대신 암호문 답의 완전 일치만 봅니다. 완전 일치는 문제 점수 10점과 같으므로 부분 점수가 있는 실제 채점보다 엄격한 지표입니다.

위 절차는 2026-11-19 갱신까지의 방식입니다. 재학습 평가부터는 1번 다음에 아래 재학습이 들어가고, 2–7번은 다시 학습한 모델로 똑같이 합니다.

### 재학습 평가 (2026-11-25(수) 평가부터)

1. 교수자 PC가 `submission/train_config.json`을 먼저 검사합니다. 파일이 없거나, JSON 객체가 아니거나, `epochs`·`batch_size`·`lr` 중 하나가 없거나, `epochs`가 1 이상의 정수가 아니거나 **상한 200을 넘으면** 학습하지 않고 채점 불가로 처리합니다. 통과하면 `train.py`와 바로 아래의 `.py`·`.json`·`.md` 파일(각 50KB 이하)만 학습 환경에 복사합니다. `checkpoint.pt`와 그 밖의 파일(데이터, weight 파일)은 넣지 않습니다.
2. 학습 환경은 네트워크가 끊긴 격리 환경입니다. `requirements.txt`와 같은 torch 2.8.0(CUDA 빌드), GPU 1개(GTX 1080 Ti, 11GB), CPU 4개, 메모리 8GB, **학습 시간 상한 1,800초**입니다. 이 GPU(compute capability 6.1)에서는 `torch.compile`을 쓸 수 없고 bf16은 느리므로, float32 또는 float16 autocast를 씁니다.
3. 학습 데이터는 `level5/train.txt`(hidden train 1,800줄)와 `level5/val.txt`(hidden val 180줄)뿐입니다. 공개 데이터와 형식·줄 수·만드는 방식·단계 규칙·기호 집합이 같고, **키와 문제만 다릅니다**. val은 early stopping 등 학습 중 확인에 써도 됩니다. 공개 데이터와 hidden test 정답은 학습 환경에 없습니다.
4. 실행 명령은 다음과 같습니다. 모든 제출에 같은 seed를 줍니다.

   ```bash
   python /sub/train.py --data /data --out /out --seed 0
   ```

   | 인자 | 내용 |
   |---|---|
   | `--data` | `level5/train.txt`, `level5/val.txt`가 있는 읽기 전용 폴더. 본인 PC에서는 `data`(공개 데이터)를 줌 |
   | `--out` | 쓰기 가능한 유일한 폴더. `checkpoint.pt`(필수)를 저장하고, 필요하면 `config.json`·`tokenizer.py`도 저장 |
   | `--seed` | 난수 seed. 같은 값이면 같은 결과가 나오도록 씀 |

   `/sub`(제출 코드)는 읽기 전용이므로 학습 결과는 `--out`에만 씁니다. 작업 폴더도 `--out`입니다.
5. 학습이 끝나면 `--out`의 `checkpoint.pt`와, `--out`에 있으면 그 `config.json`·`tokenizer.py`(없으면 제출본)를 제출한 `model.py`·`README.md`와 묶어 위 평가 절차 3–7번으로 채점합니다. parameter 300,000 상한도 학습이 끝난 모델로 검사합니다.
6. 재현성 비교를 위해 제출한 `checkpoint.pt`(공개 데이터로 학습)도 공개 데이터와 같은 키로 만든 hidden test로 채점해 교수자가 확인합니다. 두 점수 차이가 학습 seed·GPU 차이로 설명되지 않을 만큼 크면 코드를 직접 확인합니다.

**epoch와 시간 상한.** epoch는 `--data`의 train 줄 전체를 한 번씩 쓰는 것입니다. 같은 줄을 데이터 증강이나 반복으로 여러 번 쓰면 그만큼 epoch를 더 쓴 것으로 세고, 모델을 여러 개 학습하면 각 모델의 epoch를 더합니다. `train_config.json`의 `epochs`가 상한 이하이면 시간 제한으로 중단되지 않도록 시간 상한을 정했습니다. 교수자 PC GPU에서 300,000 parameter 이하의 여러 구성을 baseline과 같은 방식(float32, batch 8과 32)으로 재어 보니 가장 느린 구성(23 layer, 32차원)이 epoch당 약 4.0초였고, 상한 200 epoch × 4.0초 × 여유 2배를 올려 **1,800초**로 정했습니다. baseline은 epoch당 약 0.37초입니다. 다만 이보다 훨씬 깊고 좁은 모델(예: 40 layer 이상), batch 8 미만, epoch마다 val 전체를 greedy decoding하는 검증처럼 epoch당 시간이 크게 늘어나는 방식은 이 계산 밖입니다. 안전장치로 1,800초를 넘기면 그때까지 학습한 것도 채점하지 않으므로, leaderboard의 epoch당 시간으로 본인 설정을 확인합니다.

다음 경우는 채점 불가입니다: `train.py` 없음, `train_config.json` 없음·오류·`epochs` 상한 초과, 학습 오류, 1,800초 초과, 학습 후 `--out`에 `checkpoint.pt` 없음.

### 두 시드 재학습 평가 원칙

두 시드 평가 기능을 검증한 뒤 아래 기준을 적용합니다.

- **유효 배치 크기**는 모델을 한 번 갱신할 때 사용하는 문제 수이며 학생이 정합니다. 평가기는 11GB GPU의 메모리에 맞춰 **마이크로배치 크기**(GPU에 한 번에 올리는 문제 수)의 상한을 정해 학습 코드에 전달합니다. 학습 코드는 **그래디언트 누적**으로 작은 묶음의 계산을 모아서, 학생이 정한 유효 배치마다 모델을 한 번 갱신합니다. 예를 들어 학생이 유효 배치를 64로 정하고 평가기가 한 번에 8개까지 허용하면, 문제를 8개씩 여덟 번 계산한 뒤 모델을 한 번 갱신합니다. 마이크로배치 상한을 받는 방법은 평가기와 예제 코드 검증 후 안내합니다.
- 모든 학생의 모델을 같은 두 시드(0, 1)로 처음부터 두 번 학습합니다. 두 시드를 동시에 실행하고, GPU 메모리가 부족하면 제출 설정 그대로 한 번에 하나씩 실행합니다. 한 시드만 실행해도 GPU 메모리가 부족하면 채점 불가로 표시합니다.
- 두 시드의 **최종 점수**와 **비공개 시험 손실**을 각각 평균 냅니다. 평균 최종 점수 순위와 평균 비공개 시험 손실 순위를 50%씩 반영해 종합 순위를 정합니다.

### 재학습 평가의 학습 규칙

**공지 · 2026-11-26** — 이후 재학습 평가에서 `train_config.json`의 `batch_size`는 **1~32 사이의 정수**여야 합니다. 학습 코드에서 한 번에 GPU에 올리는 문제 수도 최대 32개입니다. 예를 들어 `batch_size: 32`는 사용할 수 있고 `batch_size: 33`은 채점 불가입니다. 이 상한은 현재 평가에 적용하며, 평가기가 마이크로배치 상한을 따로 전달하는 기능은 검증 후 적용합니다.

- 학습 예는 `--data`의 train/val 줄만 씁니다. 데이터에서 추론한 키·규칙으로 **train에 없는 새 문제와 답을 만드는 생성기**나, 암호문을 평문으로 바꾸는 **해독기**를 학습 코드에 넣지 않습니다. 재학습 데이터는 키가 달라서 공개 데이터로 알아낸 대응표는 맞지 않고, 이런 코드는 학습 알고리즘이 아니라 암호 풀이를 평가하게 만듭니다.
- 공개 train/val 줄이나, 그 데이터에서 만든 대응표·통계표를 코드나 설정 파일에 넣지 않습니다.
- 학습 하이퍼파라미터(epoch 수, batch 크기, learning rate, schedule, early stopping 기준 등)는 모두 `train_config.json`에 두고 `train.py`가 이 파일에서 읽습니다. 코드에 고정하지 않습니다. 필수 키는 `epochs`, `batch_size`, `lr`이고 다른 키는 자유롭게 추가합니다. `epochs`는 실제로 학습하는 epoch 수의 최댓값입니다(early stopping으로 더 일찍 끝나는 것은 괜찮습니다).
- train/val 줄을 고르는 순서·비율, curriculum, dropout 같은 regularization, loss를 거는 위치처럼 학습 방법을 바꾸는 것은 자유입니다.
- 학습 중 만드는 모든 모델(teacher, 보조 모델 포함)은 각각 300,000 parameter 이하이고, 모든 모델의 epoch 합이 `epochs` 이하이며, 모두 시간 상한 안에서 학습합니다. 외부 데이터·외부 weight·외부 API 출력은 쓸 수 없고 네트워크도 없습니다.
- 토크나이저가 데이터에서 만든 기호 묶음을 쓴다면, 그 묶음을 `train.py`가 `--data`에서 다시 만들어 `--out/tokenizer.py`로 저장해야 합니다. 문자 단위 토크나이저는 기호 집합이 같으므로 그대로 동작합니다.
- 학습 결과를 보고 고른 checkpoint를 손으로 넣는 방식은 쓸 수 없습니다.
- 본인 PC의 `data/`로 `python submission/train.py --data data --out <폴더> --seed 0`을 실행해 dev 점수와 epoch당 시간을 확인합니다. 재학습 데이터는 키와 문제만 다르고 크기와 만드는 방식이 같으므로, 본인 PC의 dev 점수가 재학습 점수의 가장 가까운 추정치입니다.

### 문제 점수 (문제 하나, 10점 만점)

```text
문제 점수 = round(10 × 위치가 같은 일치 단어 수 / max(정답 단어 수, 모델 답 단어 수))
```

- 해독한 모델 답을 공백으로 나누어 정답과 **같은 위치의 단어끼리** 비교합니다.
- 분모가 `max(정답 단어 수, 모델 답 단어 수)`이므로, 정답보다 단어를 더 내면 분모가 커져 감점됩니다.
- 해독되지 않는 출력(변환 규칙에 맞지 않는 기호열)은 0점입니다. 64토큰까지 `<EOS>`가 나오지 않으면 그때까지의 출력으로 채점합니다.
- `round`는 Python 반올림입니다. 정확히 .5이면 짝수 쪽으로 갑니다(7.5 → 8, 2.5 → 2).

**쉬운 예제.** 정답이 3단어 `cat dog fox`인 가상의 문제입니다.

| 해독한 모델 답 | 위치별 비교 | 계산 | 문제 점수 |
|---|---|---|---:|
| `cat dog fox` | 3개 모두 일치 | 10 × 3 / max(3, 3) = 10 | 10 |
| `cat fox dog` | 1번째만 일치 | 10 × 1 / max(3, 3) = 3.33 | 3 |
| `cat dog` | 1·2번째 일치, 1단어 빠짐 | 10 × 2 / max(3, 2) = 6.67 | 7 |
| `cat dog fox ant` | 3개 일치, 1단어 더 냄 | 10 × 3 / max(3, 4) = 7.5 | 8 |
| `dog fox` | 한 칸씩 밀려 모두 불일치 | 10 × 0 / max(3, 2) = 0 | 0 |
| 해독 불가 | - | - | 0 |

정답이 1단어 `blue`이면 `blue`는 10점, `blue sky`는 10 × 1 / 2 = 5점, `sky blue`는 첫 단어가 달라 0점입니다. 정답 단어만 정확한 순서로 내야 만점입니다.

### score (leaderboard 점수, 0–10000 정수)

```text
score = int(round(1000 × hidden test 문제 점수의 평균))
```

- 예: 문제 점수 평균이 7.8이면 score = 7800입니다.

### 종합 순위 기준

최종 점수(score)는 높은 순으로, 비공개 시험 손실(hidden loss)은 낮은 순으로 순위를 매깁니다. 두 순위를 더해 2로 나눈 평균이 작을수록 종합 순위가 높습니다. 예를 들어 최종 점수 3위, 비공개 시험 손실 1위면 평균 순위는 2.0입니다. 각 지표나 평균 순위가 같으면 공동 순위로 처리합니다.

비공개 시험 손실은 모델이 정답을 얼마나 확신했는지를 재는 값입니다. 정답 암호문(`<EOS>` 포함)을 앞에서부터 한 토큰씩 보여 주며 다음 정답 토큰의 확률 p를 읽고, `-ln p`를 모두 더해 정답 글자 수로 나눕니다. 문제마다 계산해 hidden test 문제 전체로 평균합니다. 예: 정답 `cmvf`(4글자)의 토큰 `c`, `m`, `v`, `f`, `<EOS>`에 모델이 준 확률이 0.9, 0.8, 0.9, 0.9, 0.5이면 (0.105 + 0.223 + 0.105 + 0.105 + 0.693) / 4 = 0.308입니다. 둘 다 맞혔더라도 정답을 더 확신한 모델의 hidden loss가 낮습니다.

### 왜 공정한가

| 걱정 | 이 평가가 막는 방법 |
|---|---|
| 정답을 미리 보거나 손으로 고치기 | hidden test 문제와 정답은 교수자 PC 밖으로 나가지 않습니다. 여러분은 예측 파일이 아니라 모델을 제출하고, 채점기가 직접 답을 생성합니다. |
| 실행 환경이나 decoding 방식의 차이 | 모든 제출을 같은 PC, 같은 격리 환경, 같은 greedy decoding으로 실행합니다. 학생 코드는 decoding과 채점에 관여하지 않습니다. |
| 토큰화 방식에 따른 유불리 | 점수는 토큰이 아니라 해독한 평문 단어로 비교합니다. hidden loss도 토큰 수가 아니라 정답 글자 수로 나누므로, 문자 단위와 기호 묶음 단위 토크나이저가 같은 기준으로 비교됩니다. |
| 후보 답을 여러 개 나열해 하나라도 맞히기 | 위치별로 비교하고 단어를 더 내면 분모가 커지므로, 나열하면 점수가 깎입니다. |
| 일부만 맞힌 답과 전부 틀린 답이 같은 점수 | 단어 단위 부분 점수를 줍니다. `cat fox dog`(3점)은 `dog fox`(0점)보다 높습니다. |
| 매주 공개되는 점수에 맞춰 hidden test를 외우기 | 기간 중에는 public split 점수만 공개하고, 최종 순위는 한 번도 공개되지 않은 private split으로 정합니다. |
| 큰 모델이나 외부 자원으로 이기기 | parameter 300,000 상한과 외부 데이터·weight 금지로 자원 경쟁이 아니라 설계와 실험 경쟁이 되게 합니다. 재학습 평가부터는 300,000 parameter보다 큰 teacher도 금지하고, 모든 제출을 같은 GPU·같은 epoch 상한·같은 시간 상한으로 다시 학습합니다. |
| 공개 train에서 키를 알아내 가능한 문제를 모두 만들어 학습하기 | 재학습 평가는 공개하지 않은 다른 키의 hidden train/val로 학습하고 같은 키의 hidden test로 채점하므로, 공개 데이터로 알아낸 키로 만든 데이터와 그 데이터로 미리 학습한 weight는 도움이 되지 않습니다. |
| 본인 PC의 GPU·학습 시간 차이 | 재학습 평가에서는 제출 weight가 아니라 교수자 PC에서 다시 학습한 모델을 채점합니다. 학습 알고리즘이 같으면 누가 학습해도 같은 조건입니다. |
| 점수 가중치를 임의로 정하기 | 최종 점수 순위와 비공개 시험 손실 순위를 50%씩 반영해 누구나 평균 순위를 계산할 수 있습니다. |
| 채점이 맞았는지 확인할 수 없음 | 마감 후 문제마다 평문 문제, 정답, 모델 답, 해독 결과, 점수 근거를 담은 채점표와 평문을 공개합니다. |

추론 시간은 측정할 때마다 조금씩 달라질 수 있어 참고값으로 표시합니다.

## 11. 자주 묻는 질문

**Q. 왜 평문 영어가 아니라 암호문인가?**
평문 영어라면 학습 없이도 문제를 풀 수 있습니다. `model.py`에 "Tom has 3 . Ana has 5"를 읽어 계산하는 규칙 프로그램을 직접 짜거나, 영어 단어 지식을 코드에 넣는 방식입니다. 그러면 점수가 학습 알고리즘이 아니라 손으로 짠 코드로 갈립니다. 암호문은 대응표를 데이터에서 배우지 않으면 풀 수 없는 언어를 만들어, 모델이 학습한 만큼만 점수가 나오게 합니다.

**Q. 왜 교수자 PC에서, 공개하지 않은 다른 키로 만든 데이터로 다시 학습하고 평가하는가?**
공개 데이터의 키는 분석으로 알아낼 수 있고, 키를 알면 가능한 문제를 모두 만들어 학습할 수 있습니다. 재학습 평가의 hidden train/val과 hidden test는 공개하지 않은 다른 키로 만들었으므로, 공개 데이터로 알아낸 키나 그 키로 만든 데이터, 미리 학습한 weight는 도움이 되지 않습니다. 또 모든 제출을 같은 GPU·같은 epoch 상한·같은 seed로 다시 학습하므로, 본인 PC의 자원 차이와 무관하게 학습 알고리즘과 연구 내용만으로 점수가 갈립니다.

**Q. 공개 데이터와 키가 다르면 본인 PC에서 한 실험이 소용없지 않은가?**
아닙니다. hidden train/val은 공개 train/val과 크기(1,800/180줄), 문제를 만드는 방식, 변환 규칙이 같고 키와 문제만 다릅니다. 비유하면 같은 출판사가 같은 방식으로 만든 다른 외국어 문제집으로 공부하는 것과 같습니다. 그래서 공개 데이터로 고른 모델 구조, epoch 수, early stopping 규칙, learning rate가 재학습에서도 그대로 통합니다. 다만 비유와 달리, 공개 데이터에서 외운 기호와 뜻의 대응은 키가 다르므로 옮겨 가지 않습니다.

**Q. 왜 `train_config.json`이 필요한가?**
epoch 상한(200)과 시간 상한(1,800초)을 학습 전에 확인하기 위해서입니다. 상한 이하의 `epochs`면 시간 제한으로 중단되지 않도록 시간 상한을 정했으므로, 학습이 시간 때문에 잘릴 걱정 없이 하이퍼파라미터를 고를 수 있습니다.
