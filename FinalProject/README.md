# 기말프로젝트: Tiny Synthetic Language Modeling

작은 GPT 계열 언어모델을 직접 설계하고 학습해, 공개되지 않은 암호문 문제의 답을 가장 정확하게 맞히는 과제입니다.
자연어 성능 경쟁이 아니라, 모델이 **비공개 규칙으로 만들어진 언어를 얼마나 잘 학습하고 일반화하는지** 봅니다.

## 1. 용어

- **평문**: 교수자가 만든 제한된 영어 문제와 답. 공개하지 않습니다.
- **암호문**: 평문을 비공개 변환 규칙으로 바꾼 문자열. 여러분에게 주어지는 데이터는 모두 암호문입니다.
- **단계(level)**: 변환 규칙의 등급. 1–5단계가 있고, 단계가 오를수록 규칙이 더 섞입니다. 단어를 기호로 1:1 바꾸는 방식이 아니며, 규칙은 공개하지 않습니다. 처음에는 **1단계**만 공개하고, 지금까지 공개된 단계는 `data/` 폴더와 `LEADERBOARD.md`에서 확인합니다.
- **해독**: 교수자 채점기가 암호문 답을 평문으로 되돌리는 과정. 학생 코드는 해독에 관여하지 않습니다.

## 2. 주어진 것

| 경로 | 내용 |
|---|---|
| `data/level1/train.txt` | 1단계 학습 데이터 1,800줄. 형식은 `암호문 문제<SEP>암호문 답<EOS>` |
| `data/level1/val.txt` | 1단계 개발 데이터 180줄. 형식은 train과 같음 |
| `submission/model.py` | baseline GPT. `build_model(config)`와 `forward(idx)`를 제공 |
| `submission/tokenizer.py` | 문자 단위 토크나이저. `encode`, `decode`, `SEP_ID`, `EOS_ID` 제공 |
| `submission/config.json` | 모델 하이퍼파라미터 |
| `train.py` | baseline 학습. `submission/checkpoint.pt`를 저장 |
| `dev_score.py` | 개발 점수 확인. 암호문 답의 완전 일치만 봅니다 |
| `requirements.txt` | 허용 패키지 목록 (`torch==2.8.0`) |

hidden test(비공개 테스트 문제)는 주지 않습니다. hidden test는 train과 같은 방식으로 만든 처음 보는 문제이며, 단계마다 public split 180문제와 private split 180문제입니다. 최종 채점은 교수자 PC에서 실행합니다.

## 3. 데이터와 과제

### 데이터

- 한 줄이 문제 하나입니다. 형식은 `암호문 문제<SEP>암호문 답<EOS>`이고, `<SEP>`와 `<EOS>`는 암호화하지 않는 예약 문자열입니다.
- 평문은 교수자 생성기가 만든 짧은 영어 문제와 답입니다. 어휘와 문장 틀은 작고 고정되어 있으며, 몇 가지 문제 유형이 같은 비율로 섞여 있습니다. 평문, 문제 유형, 어휘, 변환 규칙은 마감 전에 공개하지 않습니다.
- 암호화는 공백을 포함한 문자열 전체를 **문자 단위로** 바꿉니다. 같은 평문 글자도 위치와 앞 글자에 따라 다른 기호가 될 수 있어서, 단어를 기호 하나로 바꾸는 사전처럼 풀리지 않습니다. 기호는 ASCII와 Unicode 문자를 함께 씁니다.
- 1단계 기준으로 한 줄은 토큰 44개 이하이고, 암호문 답은 1–15글자입니다. 해독하면 답은 1–3단어입니다.
- 단계마다 train 1,800줄, val 180줄, hidden test public 180문제, private 180문제가 있고, 모든 단계는 같은 평문 생성기를 씁니다. 단계가 오르면 변환 규칙만 더 복잡해집니다.
- hidden test는 train과 같은 생성기로 seed만 바꿔 만들었고, train·val과 평문이 똑같은 문제는 뺐습니다. hidden test에 나오는 단어는 모두 train에 수백 번 나오며, 새로운 것은 **단어들의 조합**뿐입니다. 그래서 train을 외운 모델이 아니라 규칙을 배운 모델이 높은 점수를 받습니다.

### 과제: 암호문 문제를 읽고 암호문 답을 생성하기

모델은 `암호문 문제<SEP>`를 입력받아 다음 토큰을 하나씩 생성하고, `<EOS>`를 내면 멈춥니다. `<SEP>`와 `<EOS>` 사이에 생성한 문자열이 모델의 답입니다. 모델은 평문을 볼 수 없으므로 암호문만으로 "이런 문제 뒤에는 이런 답이 온다"는 규칙을 배워야 합니다.

**쉬운 예제 (설명용 가짜 규칙).** 실제 규칙과 문제는 이것과 다르며 훨씬 복잡합니다. 설명을 위해 "알파벳은 다음 글자로, 공백은 `·`로 바꾸는" 가짜 규칙을 씁니다.

| 단계 | 내용 |
|---|---|
| 평문 문제와 답 (여러분은 볼 수 없음) | `sky color ?` → `blue` |
| train 한 줄 (여러분이 받는 형태) | `tlz·dpmps·?<SEP>cmvf<EOS>` |
| 채점 때 모델 입력 | `tlz·dpmps·?<SEP>` |
| 모델이 생성한 답 | `cmvf` 다음 `<EOS>` |
| 교수자 채점기가 해독한 답 | `blue` → 정답과 같으므로 10점 |

비유하면 외국어 문제집을 정답과 함께 받아 공부한 뒤, 처음 보는 문제를 같은 외국어로 답하는 시험입니다. 다만 실제 외국어와 달리 이 언어는 사전이나 번역기가 없고, 문제집(train)이 유일한 자료입니다.

## 6. 제약

- parameter 수는 **300,000 이하**입니다. 학습 여부와 무관하게 모델의 모든 parameter와 buffer 원소 수를 더합니다. 학습하지 않게 고정한 weight와 `register_buffer`로 등록한 tensor도 포함됩니다. `train.py`가 출력하는 값이 채점과 같은 방식입니다.
- 채점 때는 `submission/`의 제출 파일 5개만 복사해 실행합니다. `model.py`와 `tokenizer.py`는 다른 파일을 읽으면 안 되고, 각각 50KB 이하여야 합니다. weight는 `checkpoint.pt`에만 둡니다.
- 데이터는 이 저장소의 `data/` 암호문만 씁니다. 제공 데이터에서 추론한 규칙으로 직접 만든 추가 데이터는 허용합니다. 이때 생성 코드와 근거를 README에 적습니다.
- 외부 자연어 말뭉치, 외부 pretrained weight, 외부 API 출력 데이터는 사용할 수 없습니다.
- `requirements.txt`에 없는 패키지는 사용할 수 없습니다.
- `model.py`와 `tokenizer.py`는 import할 때 파일을 쓰거나, 프로세스를 실행하거나, 외부에 접속하면 안 됩니다.
- hidden test 실행 시에는 네트워크를 쓰지 않습니다.

## 8. 평가 방식

### 평가 절차

1. 교수자 PC가 여러분 저장소의 마지막 commit에서 `FinalProject/submission/`만 내려받습니다.
2. 제출 파일 5개와 소스 크기를 검사하고, 5개만 네트워크가 끊긴 격리 환경(`requirements.txt`와 같은 torch 2.8.0 CPU)에 복사합니다.
3. `checkpoint.pt`와 모델의 parameter·buffer 원소 수를 세어 300,000 이하인지 확인합니다.
4. 채점기가 hidden test 문제마다 `암호문 문제<SEP>`를 넣고 **greedy decoding**으로 답을 생성합니다. greedy decoding은 매 단계 확률이 가장 높은 토큰 하나를 고르는 방식이며, `<EOS>`가 나오거나 64토큰에 이르면 멈춥니다. 여러분의 코드는 `build_model`, `forward`, `encode`, `decode`만 실행되고 decoding과 채점에는 관여하지 않습니다.
5. 채점기가 생성된 암호문 답을 해독해 평문 단어로 바꾸고, 정답 단어와 비교해 **문제 점수**를 매깁니다.
6. 문제 점수를 단계별로 평균 내고, 공식 단계들의 평균으로 **score**를 계산합니다.
7. score가 같으면 정해진 순서의 **동점 기준**으로 순위를 가릅니다.

`dev_score.py`는 같은 생성 방식으로 val을 풀지만, 해독 대신 암호문 답의 완전 일치만 봅니다. 완전 일치는 문제 점수 10점과 같으므로 부분 점수가 있는 실제 채점보다 엄격한 지표입니다.

### 문제 점수 (문제 하나, 10점 만점)

```text
문제 점수 = round(10 × 위치가 같은 일치 단어 수 / max(정답 단어 수, 모델 답 단어 수))
```

- 해독한 모델 답을 공백으로 나누어 정답과 **같은 위치의 단어끼리** 비교합니다.
- 분모가 `max(정답 단어 수, 모델 답 단어 수)`이므로, 정답보다 단어를 더 내면 분모가 커져 감점됩니다.
- 해독되지 않는 출력(변환 규칙에 맞지 않는 기호열)은 0점입니다. 64토큰까지 `<EOS>`가 나오지 않으면 그때까지의 출력으로 채점합니다.
- `round`는 Python 반올림입니다. 정확히 .5이면 짝수 쪽으로 갑니다(7.5 → 8, 2.5 → 2).

**쉬운 예제.** 정답이 3단어 `cat dog fox`인 가상의 문제입니다.

| 해독한 모델 답 | 위치별 비교 | 계산 | 문제 점수 |
|---|---|---|---:|
| `cat dog fox` | 3개 모두 일치 | 10 × 3 / max(3, 3) = 10 | 10 |
| `cat fox dog` | 1번째만 일치 | 10 × 1 / max(3, 3) = 3.33 | 3 |
| `cat dog` | 1·2번째 일치, 1단어 빠짐 | 10 × 2 / max(3, 2) = 6.67 | 7 |
| `cat dog fox ant` | 3개 일치, 1단어 더 냄 | 10 × 3 / max(3, 4) = 7.5 | 8 |
| `dog fox` | 한 칸씩 밀려 모두 불일치 | 10 × 0 / max(3, 2) = 0 | 0 |
| 해독 불가 | - | - | 0 |

정답이 1단어 `blue`이면 `blue`는 10점, `blue sky`는 10 × 1 / 2 = 5점, `sky blue`는 첫 단어가 달라 0점입니다. 정답 단어만 정확한 순서로 내야 만점입니다.

### score (leaderboard 점수, 0–10000 정수)

```text
단계 평균 = 그 단계 hidden test 180문제의 문제 점수 평균 (0–10)
score = int(round(1000 × 공식 단계들의 단계 평균의 평균))
```

- **공식 단계**는 평가 시점까지 train/val이 공개된 단계입니다. 아직 공개되지 않은 단계는 score에 넣지 않습니다.
- 예: 1단계만 공식이고 1단계 평균이 7.8이면 score = 7800입니다. 1·2단계가 공식이고 평균이 각각 8.6, 6.1이면 score = int(round(1000 × (8.6 + 6.1) / 2)) = 7350입니다.
- 단계마다 문제 수가 같으므로 각 단계가 score에 같은 비중으로 들어갑니다.

### 동점 기준

score가 같으면 다음 순서로 앞섭니다.

1. **hidden loss가 낮은 쪽.** hidden loss는 모델이 정답을 얼마나 확신했는지를 재는 값입니다. 정답 암호문(`<EOS>` 포함)을 앞에서부터 한 토큰씩 보여 주며 다음 정답 토큰의 확률 p를 읽고, `-ln p`를 모두 더해 정답 글자 수로 나눕니다. 문제마다 계산해 공식 단계 문제 전체로 평균합니다. 예: 정답 `cmvf`(4글자)의 토큰 `c`, `m`, `v`, `f`, `<EOS>`에 모델이 준 확률이 0.9, 0.8, 0.9, 0.9, 0.5이면 (0.105 + 0.223 + 0.105 + 0.105 + 0.693) / 4 = 0.308입니다. 둘 다 맞혔더라도 정답을 더 확신한 모델의 hidden loss가 낮습니다.
2. **parameter 수가 적은 쪽.**
3. **추론 시간이 짧은 쪽.** 같은 교수자 PC에서 hidden test를 푸는 데 걸린 시간입니다.

### 왜 공정한가

| 걱정 | 이 평가가 막는 방법 |
|---|---|
| 정답을 미리 보거나 손으로 고치기 | hidden test 문제와 정답은 교수자 PC 밖으로 나가지 않습니다. 여러분은 예측 파일이 아니라 모델을 제출하고, 채점기가 직접 답을 생성합니다. |
| 실행 환경이나 decoding 방식의 차이 | 모든 제출을 같은 PC, 같은 격리 환경, 같은 greedy decoding으로 실행합니다. 학생 코드는 decoding과 채점에 관여하지 않습니다. |
| 토큰화 방식에 따른 유불리 | 점수는 토큰이 아니라 해독한 평문 단어로 비교합니다. hidden loss도 토큰 수가 아니라 정답 글자 수로 나누므로, 문자 단위와 기호 묶음 단위 토크나이저가 같은 기준으로 비교됩니다. |
| 후보 답을 여러 개 나열해 하나라도 맞히기 | 위치별로 비교하고 단어를 더 내면 분모가 커지므로, 나열하면 점수가 깎입니다. |
| 일부만 맞힌 답과 전부 틀린 답이 같은 점수 | 단어 단위 부분 점수를 줍니다. `cat fox dog`(3점)은 `dog fox`(0점)보다 높습니다. |
| 매주 공개되는 점수에 맞춰 hidden test를 외우기 | 기간 중에는 public split 점수만 공개하고, 최종 순위는 한 번도 공개되지 않은 private split으로 정합니다. |
| 큰 모델이나 외부 자원으로 이기기 | parameter 300,000 상한과 외부 데이터·weight 금지로 자원 경쟁이 아니라 설계와 실험 경쟁이 되게 합니다. |
| 점수 가중치를 임의로 정하기 | 순위는 정수 score 하나로 정하고, 다른 지표는 동점일 때만 정해진 순서로 씁니다. |
| 채점이 맞았는지 확인할 수 없음 | 마감 후 문제마다 평문 문제, 정답, 모델 답, 해독 결과, 점수 근거를 담은 채점표와 평문을 공개합니다. |

남는 한계도 있습니다. 추론 시간은 측정할 때마다 조금씩 달라서 마지막 동점 기준으로만 씁니다. hidden loss로 동점을 가른 경우에는 교수자가 해당 제출의 코드를 직접 확인합니다.

## 10. 단계 공개

- 모든 단계의 hidden test는 시작 때 고정되어 있고, 기간 중 바뀌지 않습니다.
- leaderboard 갱신 때 public split 기준 상위 3개 제출의 현재 단계의 단계 평균이 모두 9.5점 이상이면, 다음 갱신 주기에 다음 단계의 train/val을 `data/levelN/`으로 공개합니다.
- 새 단계는 공개한 갱신(목요일 09:30) 다음 갱신부터 score에 들어갑니다. 공개 여부와 판정 근거는 `LEADERBOARD.md`에 적습니다. 공개된 단계의 data는 Guide의 `FinalProject/data/levelN/`에서 본인 저장소의 같은 위치로 복사해 씁니다.
- 마감 2주 전 이후에는 새 단계를 공개하지 않습니다.
- 평문 문제는 모든 단계에서 같은 생성기로 만들고, 단계마다 변환 규칙만 달라집니다. `train.py`와 `dev_score.py`는 `data/level*/`를 모두 읽습니다.
